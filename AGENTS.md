# Инструкция для агента: как довести ru-law-skills до релиза 0.1

Ты продолжаешь проект, начатый в другой сессии. Прочитай этот файл целиком, прежде чем что-то менять. Человек, который тебя запустил, не юрист и не программист: отчитывайся ему по-русски, простыми словами.

## 1. Что это и что значит «готово»

`ru-law-skills` — плагин из скиллов (формат Agent Skills: папка со `SKILL.md`) по российскому праву для бизнеса, юристов и разработчиков. Каркас готов: манифесты, общие правила, скилл-маршрутизатор `ru-law`, десять заготовок скиллов с техническим заданием, тестовые задачи и скрипт проверки.

**Релиз 0.1 готов, когда:**
- во всех десяти заготовках тело написано, раздел «ТЗ для разработчика» и пометка «СТАТУС: заготовка» удалены;
- у каждого скилла есть `references/norms.md`, где каждая норма сверена с официальным источником и имеет дату проверки;
- `python scripts/check.py --release` пишет «ИТОГ: ок»;
- тестовые задачи из `tests/CASES.md` прогнаны, результаты записаны в `tests/RESULTS.md`;
- в README обновлена таблица статусов, в `CHANGELOG.md` есть запись о 0.1.0.

Главная ценность проекта — **достоверность**. Скилл, который уверенно называет несуществующую статью, хуже, чем отсутствие скилла. Если приходится выбирать между полнотой и точностью, выбирай точность.

## 2. Стоп-правила (нарушать нельзя)

1. **Нет доступа к интернету или не открывается официальный источник** — не пиши нормы по памяти. Остановись и сообщи человеку, что именно не открылось.
2. **Не копируй чужое.** Не бери тексты из `anthropics/claude-for-legal`, `AlsKozlov/ru-legal`, других репозиториев скиллов, комментариев КонсультантПлюс и Гаранта, статей юристов. Пиши своими словами. Тексты законов цитировать можно (официальные документы не охраняются авторским правом), но коротко — 1–2 предложения, остальное пересказывай.
3. **Не публикуй.** Не делай `git push`, не создавай удалённый репозиторий, не делай его публичным. Локальные коммиты — можно и нужно. Публикацию делает человек сам или после его явного согласия в чате.
4. **Никаких реальных персональных данных** в репозитории: только вымышленные имена, ИНН вида `[___]`, адреса-заглушки.
5. **Не переименовывай скиллы и не меняй `shared/core-rules.md`** без согласия человека. Если правила всё же изменились — запусти `python scripts/check.py --fix`, чтобы они обновились во всех скиллах.
6. **Не меняй файлы вне этой папки.**

## 3. Устройство репозитория

```
.claude-plugin/plugin.json        манифест плагина (Claude Code)
.claude-plugin/marketplace.json   чтобы ставить через /plugin marketplace add
shared/core-rules.md              10 общих правил; скрипт вписывает их в каждый SKILL.md
skills/ru-law/                    маршрутизатор (готов)
skills/ru-*/SKILL.md              заготовки с разделом «ТЗ для разработчика»
skills/ru-*/references/           справочники: norms.md (обязательно), practice.md, чек-листы
skills/ru-*/assets/               шаблоны документов (претензия, политика, согласие и т. п.)
scripts/check.py                  проверка; --fix синхронизирует правила; --release строгий режим
tests/CASES.md                    тестовые задачи по каждому скиллу
tests/RESULTS.md                  создаёшь ты: результаты прогонов
OPEN_QUESTIONS.md                 создаёшь ты: вопросы к человеку и юристу
```

Блок между `<!-- CORE-RULES:START -->` и `<!-- CORE-RULES:END -->` в каждом SKILL.md руками не редактируй — его пишет скрипт.

## 4. Порядок работы

**Этап A — образец.** Полностью сделай `ru-contract-review` по разделу 5. Закоммить. **Остановись**, покажи человеку итог (что получилось, сколько норм сверено, результаты тестов) и дождись его «ок». Этот скилл — эталон стиля и глубины для остальных.

**Этап B — остальные скиллы** в таком порядке: `ru-pretrial-claim`, `ru-contract-draft`, `ru-personal-data`, `ru-online-terms`, `ru-copyright`, `ru-employment`, `ru-lawsuit`, `ru-advertising`, `ru-trademark`. После каждого — проверка скриптом и коммит. После каждых трёх скиллов — короткий отчёт человеку (раздел 8).

**Этап C — финал.** `python scripts/check.py --release`, таблица статусов в README, `CHANGELOG.md` с записью 0.1.0, версия `0.1.0` в `.claude-plugin/plugin.json`, итоговый отчёт. Если доступна команда `claude`, запусти `claude plugin validate .` — предупреждения про `CLAUDE.md` (он для разработчиков, а не для плагина) и про иконку можно оставить, иконку подберёт человек.

Если на каком-то скилле застрял (норма не находится, непонятно, как правильно), запиши вопрос в `OPEN_QUESTIONS.md` и переходи к следующему скиллу, а не придумывай.

## 5. Как сделать один скилл

### 5.1. Прочитай
Заготовку `skills/<скилл>/SKILL.md` (особенно «ТЗ для разработчика»), его раздел в `tests/CASES.md` и готовый `ru-contract-review` как образец (на этапе B).

### 5.2. Сверь нормы
В ТЗ есть «нормы-кандидаты» — они написаны по памяти и **не проверены**. Для каждой:

1. Открой статью на официальном источнике. Порядок: `publication.pravo.gov.ru` или `pravo.gov.ru` (официальная публикация) → `consultant.ru` или `garant.ru` (актуальная редакция со всеми изменениями). Открывай конкретную статью, а не весь кодекс.
2. Убедись, что статья **действует сейчас**, и посмотри, нет ли изменений, которые вступят в силу позже (КонсультантПлюс пишет это в начале документа). Если есть — отметь в колонке «Суть».
3. Проверь, что статья говорит то, что утверждает ТЗ. Если номер другой или смысл иной — исправь. Если такой нормы нет — удали и запиши в `OPEN_QUESTIONS.md`.
4. Добавь недостающие нормы, без которых тема не раскрыта.
5. Каждая цифра (штраф, пошлина, порог, срок) — отдельной строкой.

Формат `references/norms.md` (скрипт проверяет заголовок, ссылку и дату):

```markdown
# Нормы: <название скилла>

Сверено: ГГГГ-ММ-ДД. Перед использованием цифр (штрафы, пошлины, сроки) перепроверять.

| Норма | Суть | Источник | Редакция | Проверено |
|---|---|---|---|---|
| ГК РФ ст. 432 | Договор заключён, когда стороны согласовали все существенные условия... | https://www.consultant.ru/document/cons_doc_LAW_5142/... | ред. от ДД.ММ.ГГГГ | ГГГГ-ММ-ДД |
```

«Суть» — 1–2 предложения своими словами, без выводов сверх текста нормы. «Проверено» — дата, когда ты **действительно открыл** источник.

**Судебная практика** — только постановления Пленума ВС РФ и обзоры Президиума ВС РФ, открытые на `vsrf.ru` или `consultant.ru`, в отдельном файле `references/practice.md` в том же формате. Не больше 5–7 на скилл. Номера конкретных дел не приводи.

### 5.3. Напиши тело SKILL.md
Заполни разделы «Что спросить», «Порядок работы», «Чек-лист», «Формат результата», «Нормы» по ТЗ.

- **Объём:** SKILL.md — до 300 строк. Длинные чек-листы, шкалы, библиотеки формулировок выноси в `references/`, шаблоны документов — в `assets/` (Markdown с заглушками `[___]`). В тексте SKILL.md прямо скажи, когда какой файл читать.
- **Ссылки на нормы** в тексте скилла — только на те, что есть в `norms.md`, в виде «ГК РФ ст. 432 (см. `references/norms.md`)».
- **Стиль:** повелительное наклонение, коротко, с объяснением *зачем* («спроси, кто стороны: от этого зависит, применяется ли закон о защите прав потребителей»), а не КАПСОМ и «ВСЕГДА/НИКОГДА». Пример плохого пункта: «Проверь ответственность». Хорошего: «Сравни неустойку сторон: если она есть только у нашей стороны или в разы больше, предложи симметричную или верхний предел — иначе мелкая просрочка обернётся крупной суммой».
- **Связи:** где тема пересекается с другим скиллом, пиши «подробнее — скилл `ru-...`».
- **description** во frontmatter можно уточнять, но: в двойных кавычках, без двойных кавычек внутри (используй «ёлочки»), до 1024 символов, с фразами, которыми пользователи реально формулируют запрос.

### 5.4. Убери ТЗ и проверь
Удали раздел «ТЗ для разработчика» и строку «СТАТУС: заготовка», затем:

```
python scripts/check.py
```

Скилл должен получить статус «готов», ошибок быть не должно.

### 5.5. Прогони тесты
Для каждой задачи скилла из `tests/CASES.md`: один прогон **со скиллом**, один **без** — каждый в новом чистом контексте (отдельная сессия или субагент). Сравни с пунктами «Должно быть / Не должно быть», запиши в `tests/RESULTS.md` по форме из конца `CASES.md`. Отдельно проверь каждую статью, которую назвал ответ со скиллом: есть ли она в `norms.md`. Названная статья вне справочника — это дефект скилла.

Если запустить чистый контекст не можешь, так и напиши в RESULTS.md («не прогнано, причина») — не выдумывай результаты.

### 5.6. Исправь и закоммить
Исправь найденное, при серьёзных правках прогони тесты повторно. Затем:

```
git add -A
git commit -m "<скилл>: тело скилла и справочник норм (сверено ГГГГ-ММ-ДД)"
```

## 6. Как проверить скилл в деле

- **Claude Code:** `/plugin marketplace add <путь к этой папке>`, затем `/plugin install ru-law@ru-law-skills`, перезапуск.
- **Другие агенты со стандартом Agent Skills:** скопируй нужные папки из `skills/` в папку скиллов агента (путь — в документации агента).
- **claude.ai:** заархивируй папку скилла в zip и загрузи в настройках скиллов.

## 7. Чего не делать ради экономии ресурсов

- Не скачивай кодексы целиком — открывай конкретные статьи.
- Не перечитывай уже сверенные нормы в другом скилле: если норма уже есть в чужом `norms.md` с датой не старше 30 дней, можно перенести строку как есть.
- Не прогоняй тесты повторно без изменений в скилле.

## 8. Отчёт человеку

Коротко, по-русски, без жаргона:

```
Готово: <скиллы>
Сверено норм: <число>, источники: <какие>
Тесты: <сколько задач прошло со скиллом / без скилла>
Не получилось: <что и почему>
Вопросы (OPEN_QUESTIONS.md): <число>, главные: ...
Следующий шаг: ...
```

Не пиши «всё готово», если `check.py --release` не проходит или тесты не прогнаны.
